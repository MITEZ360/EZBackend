# 决策日志（Lightweight ADR）

> 记录「为什么这样设计」而非「做了什么」。功能清单与用法见 [README](../README.md)，
> 实现细节见各功能文档。新增重要取舍时追加一条，编号递增，不修改历史条目。

格式：**编号 / 日期 / 状态 / 背景 → 决定 → 后果（含代价）**。

---

## #1　2026-11-02　核心能力走 main，业务衍生功能开分支

- **背景**：项目既要沉淀可复用的通用后台能力，又要尝试资讯聚合这类业务功能；两者混在同一分支会让主线不稳定。
- **决定**：通用能力（认证、RBAC、API Key、会员、迁移、备份、OAuth、文档）直接提交 `main`；业务衍生功能在 `feature/*` 分支开发验证后再合并。
- **后果**：主线始终可发布；资讯聚合在 `feature/news-hub` 完成验证后合入。代价是需要维护分支纪律。

## #2　2026-11-03　运行时零 Node 依赖，前端产物嵌入单二进制

- **背景**：目标交付形态是中小企业可私有化部署的单进程服务，运维不希望额外维护 Node 进程。
- **决定**：前端用 Vue3 + Vite 仅参与构建，`web/dist` 通过 `go:embed all:dist` 打进 Go 二进制；运行时纯 Go。
- **后果**：交付只有一个可执行文件；代价是前端改任何内容都要重新编译 Go 二进制，热更新需另配 CDN 或反向代理。

## #3　2026-11-04　会员到期不删数据，按当前时间实时判定

- **背景**：用户会员到期后，是否被抹成"非会员"？若定时任务改库，会有延迟和状态不一致。
- **决定**：用户表只存等级 ID 与到期时间；是否会员由 `MembershipState()` 按当前时间实时计算；同等级续费顺延、换等级重算。
- **后果**：无定时任务漂移，状态永远准确；代价是每次查询用户状态都要做一次时间比较（成本极低）。

## #4　2026-11-12　API Key 只存 SHA-256 与前缀，签发时回显一次明文

- **背景**：机器身份密钥若明文入库，一旦数据库泄露全部失守。
- **决定**：`ak_s_`（服务端）/ `ak_c_`（客户端）前缀区分类型；库里只存 SHA-256 与前 12 位（用于展示与检索）；明文仅在创建/轮换时回显一次。
- **后果**：DB 泄露不直接暴露可用密钥；代价是用户丢失明文后只能轮换、无法找回。

## #5　2026-11-12　资讯来源与分类改为系统白名单，图标随元数据下发

- **背景**：初版资讯的来源、分类是爬虫自由字符串，脏数据难治理，客户端也不知道有哪些合法分类与图标。
- **决定**：`NewsSource` / `NewsCategory` 由后台预配置（含 `icon/color/sort`）；爬虫推送时未配置来源整批拒绝、非法分类单条标 `invalid` 且批次继续；`category` 必须显式传，不兜底 `general`；开放端 Meta 接口全量下发来源与分类（含图标 URL）。
- **后果**：数据可控、客户端可渲染一致的分类导航；代价是新增分类需先在后台配置。图标 URL 走本地 `/uploads` 静态路由，因此备份必须纳入文件资产（见 #9）。

## #6　2026-11-12　游标分页而非 offset，时间统一 UTC

- **背景**：资讯按时间倒序浏览，offset 分页在持续写入时会重复/漏项；本地时间与 UTC 混用导致排序错乱。
- **决定**：用 `(published_at, id)` 复合游标分页；全链路时间统一 `time.Now().UTC()` 与 `PublishedAt.UTC()`，SQLite 中以格式化字符串比较。
- **后果**：滚动加载稳定不重复；代价是只能单向翻页，不能跳到第 N 页。

## #7　2026-11-13　OAuth 令牌经 URL fragment 回传，而非 query

- **背景**：第三方登录后要把本地 JWT 交回前端。放 query 会被浏览器历史、服务器日志、Referer 记录。
- **决定**：回调后重定向到前端，令牌放在 `#` 之后的 fragment（`#access_token=...&refresh_token=...`），前端 `oauth/callback` 页解析 fragment 写入登录态。
- **后果**：令牌不经服务器、不留日志；代价是需要一个专门的前端回调页来接收。

## #8　2026-11-13　OAuth 绑定表唯一约束用两列组合，冲突返回 409

- **背景**：初版把 `user_id/provider/subject` 三列一起做唯一键，导致同一外部账号可绑多个本地用户；绑定流程查到他人绑定会直接返回该用户，前端提示"已绑定"但关系并未建立。
- **决定**：v4 迁移拆为 `uk_oauth_subject(provider, subject)` 与 `uk_oauth_user_provider(user_id, provider)`；`resolveUser` 在 bind 模式发现外部账号属于他人时返回 409；并发唯一键错误转可读提示。物理清理旧重复行再重建索引。
- **后果**：一个外部账号只能属于一个本地用户，冲突显式报错；代价是追加了一次不可逆的数据清理迁移（`Down` 只能回退结构）。

## #9　2026-11-22　备份产物改为 tar 容器，纳入文件资产

- **背景**：备份只导数据库，但资讯图标、上传附件存于 `uploads/`；恢复后数据库完好、图片全裂（借鉴自外部项目 EZProject 的教训："内容里只有 asset id，DB 备份不含图片字节"）。
- **决定**：备份产物改为 tar 容器，内含 `database.db`、`manifest.json`、`files/`；一次下载/一次恢复拿到完整数据；对象存储模式显式跳过并标注 `storageMode`。保留对旧 `.db/.sql(.gz)` 格式的读取兼容。
- **后果**：恢复后图标可用；代价是备份文件变大、格式升级（旧备份仍可读，新备份需新版本解析）。

## #10　2026-11-22　恢复必须可演练，且永不删最新备份

- **背景**：恢复是高危操作，直接覆盖数据；简单的"保留最近 N 份"在长时间断档后可能把唯一可用备份挤出窗口。
- **决定**：`restore --dry-run` / `?dry_run=true` 只输出计划不改文件，恢复前页面自动演练；恢复后逐表比对行数、报告文件资产还原数；保留策略改为 GFS 分档按槽位挑选，最新一份永不删除，四档全 0 才退回 `retain`。
- **后果**：恢复可预期、可自检，断档不误删；代价是演练与真实恢复共用一套计划逻辑，需保证演练路径绝不写文件。

## #11　2026-11-22　架构约束交给机器：import 边界优先于业务词黑名单

- **背景**：分层依赖铁律（`modules → platform → pkg`）此前只靠人工 Review。外部项目用"内核业务词黑名单"把关，但在 Go 里 `category`、`order` 等是中性词，直接搬会误伤。
- **决定**：`scripts/check_architecture.py` 实现三条贴合 Go 的规则：① platform/pkg 不得 import modules；② 方言判断只在白名单文件；③ `pkg` 导出签名快照变更需 `--update`。纳入 `make verify`。
- **后果**：内核不被业务污染、公共 API 偷改被拦截；代价是新增公共导出或新方言分支时要更新白名单/快照。

## #12　2026-11-22　启动自检关键依赖 fail-fast，非关键只告警

- **背景**：配置错了 Redis 地址但服务"看似正常启动"，多实例状态悄悄分裂；或迁移版本落后却无人察觉。
- **决定**：`bootstrap.New` 装配后探测数据库/缓存/存储（关键项，失败即拒绝启动），迁移版本落后与种子为空只告警；报告挂 `app.SelfCheck`，启动日志打印结论。
- **后果**：问题在启动期暴露而非运行期；代价是启动多了几个探针往返（毫秒级）。

## #13　2026-11-22　跨方言验证必须在真实 MySQL/PG 上跑

- **背景**：某外部项目曾因 5 张表用 `INTEGER` 存 epoch 毫秒在 PG 上完全不可用，而 SQLite（动态类型，`INTEGER` 实为 64 位）侧测试永远发现不了。
- **决定**：`test/dialect_test.go` 用同一套断言覆盖三方言，`make test-dialect` 起临时容器；未设 DSN 时跳过，本地测试不受影响；发版前必须跑一次真库。
- **后果**：方言差异在 CI/发版前暴露；代价是跨方言测试依赖 Docker 且耗时更长，因此不放进日常 `verify`。

## #14　2026-11-22　模块可拔插采用声明式契约，不推翻现有装配

- **背景**：要让模块按配置启停，可彻底重构为注册表驱动的服务定位，但风险高、易让 159 条路由回归。
- **决定**：定义轻量 `Module` 契约（`Name/DependsOn/AlwaysOn`）与注册表，统一 `micro.modules` 与 `modules.enabled`；服务/处理器仍由 `app.go` 统一构造，路由按注册表结果挂载；基础模块常驻、依赖自动补齐、未知模块 fail-fast。
- **后果**：获得按配置裁剪与依赖自检能力，且路由零回归；代价是这不是彻底的服务定位，彻底解耦仍需未来重构（P1-2 已为它留出契约边界）。
